# Проверка реализации

Проверено 17 ноября 2026 года в локальном окружении разработки:

- Maven `verify` под Java 11: 104 теста, без ошибок и пропусков.
- Все восемь Docker-образов собраны, приложение Mule упаковано штатным Mule Maven Plugin.
- Настоящий Mule Kernel 4.9.0 загрузил оба потока; `/health` вернул HTTP 200.
- WAR ISU запущен на внешнем Apache Tomcat 9.0.124.
- `scripts/verify-lab4.py` прошёл на собранных контейнерах с PostgreSQL, Config Server,
  Eureka, Gateway, REST-адаптером, SOAP ISU, Mule и Nginx. Проверены прежний REST,
  оба SOAP-метода, WSDL, Fault 400/404, точность дат, вложенные поля и удаление групп.
- `kubectl kustomize .` сформировал 25 ресурсов; kubeconform со строгими схемами
  Kubernetes 1.37.0 подтвердил 25 валидных ресурсов, без ошибок и пропусков.
- Исходники Study Groups, его зависимости и конфигурация, общий API,
  OpenAPI и JavaScript клиента совпадают с исходным коммитом `d3d6a77`.

В интеграционном прогоне обнаружена и исправлена замена XML SOAP Fault на JSON 503
в Gateway. Добавлен регрессионный Java-тест сохранения HTTP 500 и XML для SOAP-маршрута.

Живой прогон в Kubernetes не завершён: скачивание node image для kind столкнулось
с сетевыми и TLS-таймаутами. Проверка манифестов выполнена по схемам, а прикладная
интеграция — в настоящих контейнерах. При раскатке оператор запускает
`scripts/deploy-k8s.sh` и повторяет `scripts/verify-lab4.py` в своём кластере.
Целевой стенд и Helios из этой среды не изменялись.
